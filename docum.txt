========================================================================
                     MUSIC PLAYER PROJECT DOCUMENTATION
========================================================================

This document provides a comprehensive overview of the Music Player
application architecture, file structure, OOP concepts, and build
instructions. Updated after the refactoring pass to clean up code
style and properly demonstrate BSc.IT OOP course principles.

------------------------------------------------------------------------
1. PROJECT ARCHITECTURE & FILE STRUCTURE
------------------------------------------------------------------------
The Music Player is a terminal-based, cross-platform audio player
written in C++17. It uses a Unity Build model: main.cpp #includes all
other .cpp files in dependency order, producing a single executable.

File Layout:
  MusicPlayer/
  ├── main.cpp                          <- Entry point (driver file)
  ├── song_management/
  │   └── MusicManager.cpp              <- Core classes: Song, Playlist,
  │                                        MusicManager (all OOP logic)
  └── ui/
      ├── Screen.cpp                    <- Screen enum (navigation states)
      ├── UIUtils.cpp                   <- Terminal UI utility functions
      ├── MenuSection.cpp               <- Main menu handler
      ├── LibrarySection.cpp            <- Song library view
      ├── SearchSection.cpp             <- Search interface
      ├── FavoritesSection.cpp          <- Favorites list
      ├── PlaylistsSection.cpp          <- Playlists manager
      └── NowPlayingSection.cpp         <- Now Playing view + controls

Build command (Windows):
  g++ -std=c++17 -O2 -static main.cpp -o AudioPlayer.exe -lwinmm

Or simply run:  build.bat

------------------------------------------------------------------------
2. OOP CONCEPTS DEMONSTRATED
------------------------------------------------------------------------

A. ENCAPSULATION (Song class, MusicManager class)
   ================================================
   Both Song and MusicManager use private data members with public
   getter/setter methods. External code cannot directly access the
   internal state — it must go through the public interface.

   Example (Song class):
     private:
       string title;       // hidden from outside
       string artist;
       bool favorite;
     public:
       string getTitle() const;       // controlled read access
       void setTitle(const string&);  // controlled write access

B. CONSTRUCTORS (Song, MusicManager)
   ==================================
   Song has two constructors:
     - Default:       Song()  ->  sets "Unknown Title", 0 duration, etc.
     - Parameterized: Song(title, artist, duration, path)

   MusicManager has a constructor that initializes:
     - nowPlayingIndex = -1 (nothing playing)
     - dataFilePath = "userdata.txt"

C. OPERATOR OVERLOADING (Song class)
   ==================================
   - operator==   : Compares two songs by title, artist, and duration
   - operator<<   : Allows "cout << song" to print formatted song info

D. FUNCTION OVERLOADING (MusicManager class)
   ==========================================
   addSong has 2 versions:
     - addSong(const Song&)                           // takes a Song object
     - addSong(title, artist, duration, filePath)     // takes individual fields

   renameSong has 2 versions:
     - renameSong(index, newFileName)                  // renames the file
     - renameSong(index, newTitle, newArtist)           // renames metadata only

3. MODULE-BY-MODULE ANALYSIS
------------------------------------------------------------------------

A. MAIN ENTRY POINT (main.cpp)
   ===========================
   - Calls UIUtils::setupConsole() to enable UTF-8 and ANSI escape codes
   - Creates a MusicManager object and loads saved data
   - Runs the main application loop (switch-based screen navigation)
   - Saves data and stops audio on exit

   Headers used:
   - <iostream>  (Standard Library) — console output
   - #include "song_management/MusicManager.cpp"  — core classes
   - #include "ui/Screen.cpp"                      — navigation enum
   - #include "ui/UIUtils.cpp"                     — UI utilities
   - #include "ui/*Section.cpp"                    — screen handlers

B. SONG MANAGEMENT MODULE (MusicManager.cpp)
   ==========================================
   Contains Song class, Playlist struct, and MusicManager class.
   All method implementations are defined inline (inside the class
   body) since this file is #included by main.cpp rather than
   compiled separately.

   Headers used:
   - <string>, <vector>        — data structures
   - <iostream>                — output streams
   - <sstream>, <iomanip>      — time formatting (M:SS)
   - <algorithm>, <cctype>     — case-insensitive search (toLower)
   - <chrono>                  — playback progress tracking
   - <cstdio>                  — popen/pclose for ffprobe
   - <cstdlib>                 — system() for ffplay
   - <filesystem>              — directory scanning
   - <fstream>                 — save/load user data
   - <windows.h>               — (Windows only) OS definitions

   Audio control is encapsulated in two methods:
   - startAudio(filePath) — kills existing ffplay, starts new one
   - stopAudio()          — kills all ffplay processes

C. UI UTILITIES (UIUtils.cpp)
   ============================
   Namespace with static-like utility functions:
   - setupConsole()         — enables UTF-8 + ANSI on Windows
   - clearScreen()          — ANSI cursor home (no system("cls"))
   - fullClear()            — full ANSI clear + cursor home
   - pause()                — waits for ENTER
   - readIntChoice()        — reads integer input safely
   - readSingleKeyWithTimeout() — non-blocking keypress for Now Playing
   - printBoxTop/Line/Bottom — box-drawing for the TUI layout
   - visualLength()         — UTF-8 aware string width calculation

   Headers used:
   - <string>, <iostream>, <cstdlib>, <limits>
   - <windows.h>, <conio.h>        (Windows: keyboard input)
   - <termios.h>, <unistd.h>, <fcntl.h>  (Linux: keyboard input)

D. SCREEN HANDLERS (*Section.cpp files)
   ====================================
   Each file defines a single function: showXxx(MusicManager&)
   that displays its screen and returns the next Screen to go to.

   These files do NOT have their own #includes for local dependencies.
   They rely on main.cpp's unity build to provide access to
   MusicManager, Screen, and UIUtils.

   They only #include standard library headers (<iostream>, <string>,
   etc.) for their own needs.

------------------------------------------------------------------------
4. AUDIO PROCESS WORKFLOW
------------------------------------------------------------------------
When a song is triggered, the following happens:
1. MusicManager::play(index) validates the file and records the start time
2. MusicManager::startAudio(filePath) kills any existing ffplay and
   launches a new background ffplay process using system()
3. MusicManager::getPlaybackElapsedMs() uses chrono to track progress
4. NowPlayingSection draws a progress bar and auto-advances songs
   when elapsed time >= song duration
